## 2. Agent Card e app Starlette (~50 min)

- [x] 2.2 Criar o entrypoint `agente/servidor.py` que sobe o uvicorn na porta de env (default `7300`, ex.: `A2A_PORT`), com host default `127.0.0.1`, e derivar a `url` do card da mesma configuração. **Verificação:** `A2A_PORT=7300 .venv/bin/python agente/servidor.py` sobe e `curl -s http://127.0.0.1:7300/.well-known/agent-card.json` responde `200` com JSON.

## 3. Dispatcher JSON-RPC e máquina de estados (~60 min)

- [x] 3.1 Criar `agente/controllers/a2a.py` com o dispatcher de `POST /a2a`: ler `jsonrpc`/`id`/`method`/`params`, despachar `SendMessage` e `GetTask`, e ecoar o `id` no envelope de resposta (string ou número, byte a byte). **Verificação:** `curl -s -X POST http://127.0.0.1:7300/a2a -H 'Content-Type: application/json' -d '{"jsonrpc":"2.0","id":"abc","method":"GetTask","params":{"id":"task-inexistente"}}'` devolve um JSON-RPC com `id` igual a `"abc"` (erro ou resultado).
- [x] 3.2 Implementar a abertura de Task em `SendMessage` sem `taskId`: criar a Task em `SUBMITTED` (id/contextId próprios), registrar a mensagem do usuário no `history`, transitar para `WORKING`, chamar `executar_pedido_async(texto, traceparent)` e traduzir para o estado terminal (bloco 4). **Verificação:** um `SendMessage` de sala livre (`sala-porao` 09:00–10:00) responde com `result.task` contendo `id` e `contextId` não vazios e `status.state == "TASK_STATE_COMPLETED"`.
- [x] 3.3 Implementar `GetTask` (devolver `id`, `contextId`, estado, `history` e `artifacts`) e erro JSON-RPC para Task inexistente. **Verificação:** após 3.2, `GetTask` com o `id` devolvido traz `contextId` não vazio e `status.state == "TASK_STATE_COMPLETED"`.

## 4. Tradução de resultado, artifact e terminalidade (~60 min)

- [x] 4.1 Implementar a tradução `Resultado → estado` (decisão 5 do design): `Completado(reservado=True)` → `COMPLETED` com mensagem `Reserva <id> confirmada na <sala>.` e artifact `reserva`; `Completado(reservado=False)` → `CANCELED`; `Falhou` → `FAILED` com a mensagem exata; `Pausado` → `FAILED` com mensagem determinística — **marcando esse braço como ponto de extensão da fase 5**. **Verificação:** `SendMessage` de `sala-porao` livre responde `TASK_STATE_COMPLETED` com `artifacts[0].name == "reserva"` e o JSON do artifact com `politica == "2026-11-01"` e `sala == "sala-porao"`.
- [x] 4.2 Implementar a falha de tool: `SendMessage` de sala inexistente (`sala=sala-delorean`) termina a Task em `TASK_STATE_FAILED` com a mensagem exata `Sala inexistente: sala-delorean` na mensagem de status e no histórico. **Verificação:** `curl` do pedido de sala inexistente devolve `status.state == "TASK_STATE_FAILED"` e a mensagem de status contém `Sala inexistente: sala-delorean`.
- [x] 4.3 Implementar a terminalidade definitiva: `SendMessage` com `taskId` apontando para uma Task em `{COMPLETED, FAILED, CANCELED}` devolve erro JSON-RPC (campo `error`, sem `result`), sem voltar a `WORKING`. **Verificação:** reenviar um `SendMessage` com o `taskId` da Task concluída em 4.1 devolve um objeto com `error` preenchido e sem `result.task`.
