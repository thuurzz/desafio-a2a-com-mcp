# Tasks

## 1. Estrutura e dependências (~40 min)

- [ ] 1.1 Criar `servidor-mcp/pyproject.toml` com `requires-python = ">=3.11"`, dependência travada `mcp>=2.3,<3` e os pacotes `models`, `controllers` e `views`; criar os três diretórios com `__init__.py` e o `servidor-mcp/main.py` como entrypoint. **Verificação:** `test -f servidor-mcp/pyproject.toml && ls servidor-mcp/models servidor-mcp/controllers servidor-mcp/views` e `.venv/bin/python -m pip show mcp | grep -i '^Version'` (deve mostrar `2.3.x`).
- [ ] 1.2 Instalar o projeto em modo editável e subir o app ASGI vazio em `7301`/`/mcp` com `stateless_http=True` e `json_response=True`, lendo porta e path de env com esses defaults. **Verificação:** com o processo em background, `curl -s -o /dev/null -w '%{http_code}\n' http://localhost:7301/mcp` devolve um status HTTP (não `000`), e o processo não imprime traceback no stderr.

## 2. Modelos e carga de dados (~50 min)

- [ ] 2.1 Implementar em `models/` os tipos `Sala`, `Reserva`, entradas/saídas das tools (`ListaDeSalas`, `Disponibilidade`, `ReservaOut`) e a carga única de `dados/salas.json`, `dados/reservas.json` e da versão da primeira linha de `dados/politica-de-uso.md`, somente leitura. **Verificação:** `.venv/bin/python -c "from models.dados import carregar; d = carregar(); print(len(d.salas), len(d.reservas), d.politica_versao)"` imprime `5 2 2026-11-01`.
- [ ] 2.2 Implementar em `controllers/` as funções de listagem, consulta e reserva com a ordem de validação sala → intervalo → janela → duração → sobreposição, reservas novas em memória e ids sequenciais a partir de `res-0003`; conflito com alternativas existentes não cria reserva e devolve `isError` transitório. **Verificação:** `.venv/bin/python -c "from controllers.salas import consultar; print(consultar('sala-aquario', '2026-11-03T07:00:00-03:00', '2026-11-03T08:00:00-03:00')['erro'])"` contém `Fora da janela de uso: a politica permite reservas entre 08:00 e 20:00`.

## 3. Superfície Streamable HTTP (~55 min)

- [ ] 3.1 Ligar os handlers lowlevel `on_list_tools`, `on_call_tool`, `on_list_resources` e `on_read_resource` em `views/` e declarar as capabilities `tools` e `resources`; publicar as três tools com `inputSchema` objeto e `outputSchema` em `listar_salas` e `reservar_sala`. **Verificação:** `curl -s http://localhost:7301/mcp -H 'Content-Type: application/json' -H 'Accept: application/json, text/event-stream' -H 'MCP-Protocol-Version: 2026-07-28' -H 'Mcp-Method: tools/list' -d '{"jsonrpc":"2.0","id":1,"method":"tools/list","params":{"_meta":{"io.modelcontextprotocol/protocolVersion":"2026-07-28","io.modelcontextprotocol/clientCapabilities":{"elicitation":{"form":{}}}}}}}'` devolve JSON com as três tools e cada `inputSchema.type` igual a `object`.
- [ ] 3.2 Implementar o guard de `_meta` por request (middleware ASGI em `views/`) exigindo `io.modelcontextprotocol/protocolVersion` e `io.modelcontextprotocol/clientCapabilities`, respondendo `-32602` com HTTP `400` sem despachar. **Verificação:** repetir o `curl` do item 3.1 removendo `protocolVersion` e, depois, removendo `clientCapabilities`; em ambos `curl -s -o corpo.json -w '%{http_code}' ...` imprime `400` e `python3 -c "import json;print(json.load(open('corpo.json'))['error']['code'])"` imprime `-32602`.
- [ ] 3.3 Implementar o log em stderr de cada request com método, id e `traceparent` (ou `-`), inclusive para requests rejeitados pelo guard. **Verificação:** enviar um request com `"traceparent":"00-4bf92f3577b34da6a3ce929d0e0e4736-00f067aa0ba902b7-01"` e conferir no stderr uma linha com `tools/list`, o id enviado e esse traceparent; enviar um request sem `_meta` e conferir que a linha continua aparecendo.

## 4. Tools e regras de negócio (~60 min)

- [ ] 4.1 Implementar `listar_salas` devolvendo `structuredContent` conforme o `outputSchema` e o mesmo JSON em bloco de texto. **Verificação:** `curl` de `tools/call` com `{"name":"listar_salas","arguments":{}}` e `python3 -c "import json,sys; r=json.load(sys.stdin)['result']; assert json.loads(r['content'][0]['text']) == r['structuredContent']; print('ok')"` imprime `ok` (PASS 01–03).
- [ ] 4.2 Implementar `consultar_disponibilidade` com `{sala, livre, conflitos}` e as mesmas validações de política da reserva, com as quatro mensagens literais. **Verificação:** quatro `curl` de `tools/call` para `consultar_disponibilidade` — `sala-delorean`, `07:00–08:00`, `09:00–12:00` e `10:00→09:00` — cada um com `isError: true` e o texto exato de `Sala inexistente`, `Fora da janela de uso`, `Duracao acima do limite` e `Intervalo invalido` (PASS 09–12); e `sala-garagem` em `14:00–15:00` devolve `livre: false` com `res-0001` em `conflitos`.
- [ ] 4.3 Implementar `reservar_sala` no caminho feliz, com `structuredContent` completo (`reserva`, `reservado`, `sala`, `inicio`, `fim`, `responsavel`, `politica`, `motivo`) e o mesmo JSON em texto, e o conflito sem alternativas com `isError` e a mensagem literal. **Verificação:** reservar `sala-aquario` em `2026-11-03T09:00:00-03:00`–`10:00` devolve `reservado: true` e `politica: "2026-11-01"`; reservar de novo o mesmo intervalo retorna `isError` com `Sem alternativas disponiveis no intervalo`; reservar `sala-mirante` `11:00–12:00` e repetir devolve a mesma mensagem (PASS 20).
- [ ] 4.4 Recusar `tools/call` de tool inexistente sem executar nada. **Verificação:** `curl` de `tools/call` com `{"name":"voar_delorean","arguments":{}}` devolve `result.isError: true` ou `error.code: -32602` (PASS 06).
